Introduction

The RDML7 package provides tools for importing, exporting, validating, inspecting, modifying, and converting quantitative PCR (qPCR) data represented by the Real-time PCR Data Markup Language (RDML).

RDML stores both fluorescence measurements and experimental metadata in a structured format. The format is designed to make qPCR experiments easier to exchange, reproduce, and reanalyse.

RDML7 is a major redesign of the original RDML R package described in:

Rödiger S, Burdukiewicz M, Spiess A-N, Blagodatskikh K. Enabling reproducible real-time quantitative PCR research: the RDML package. Bioinformatics 33(24), 4012–4014. https://doi.org/10.1093/bioinformatics/btx528

The original package used an R6 object model. RDML7 uses S7 classes and a primarily functional API. The main workflow is now:

file
  |
  v
readRDML()
  |
  v
rdmlType
  |
  +---- asTable() -------- metadata / curve index
  |
  +---- getFData() ------- fluorescence data
  |
  +---- setFData() ------- add or replace fluorescence data
  |
  +---- summary() ---- summary
  |
  +---- validateRDML() --- validation
  |
  +---- asDendrogram() --- hierarchy
  |
  +---- mergeRDMLs() ----- merge RDML objects
  |
  +---- writeRDML() ------ RDML / XML / RDES / other registered formats

The old names such as AsTable(), GetFData(), SetFData(), AsDendrogram(), asXML(), and MergeRDMLs() are retained as compatibility wrappers where possible. New code should use the camelCase API.

Main changes from the original RDML package

The most important changes are:

  1. S7 object model instead of R6.
  2. Value semantics: functions that modify an object return a modified object, which should normally be assigned back.
  3. CamelCase functional API, for example asTable() and getFData().
  4. Centralised file I/O with readRDML() and writeRDML().
  5. Extensible format registry with automatic format detection.
  6. Direct support for importer modules through a canonical intermediate representation.
  7. Validation and summary functions for RDML objects.
  8. RDES import/export in addition to RDML and vendor/table formats.
  9. A revised asTable() interface with documented fields and reusable {field} name templates.

A migration summary is shown below.

Loading RDML7

library(RDML7)

The package contains example RDML files that can be used throughout this vignette.

filename <- system.file(
  "extdata",
  "lc96_bACTXY.rdml",
  package = "RDML7"
)

Reading files

readRDML()

Use readRDML() as the main entry point for file import.

lc96 <- readRDML(filename)
#> 
#> Loading experiment: ca1eb225-ecea-4793-9804-87bfbb45f81d
#>  run: 65aeb1ec-b377-4ef6-b03f-92898d47488b

The default format selection is automatic. If a format is ambiguous, it can be specified explicitly.

lc96 <- readRDML(
  filename,
  format = "rdml"
)

This replaces the old pattern:

# Original RDML package
# lc96 <- RDML$new(filename = filename)

Discovering available file formats

The set of available formats is no longer hard-coded into the user-facing import function. It is stored in a registry.

formats <- listRDMLFormats()
formats
#>        format    extensions read write
#> 1         abi           eds TRUE FALSE
#> 2   rotorgene           rex TRUE FALSE
#> 3       excel     xlsx, xls TRUE FALSE
#> 4         csv           csv TRUE FALSE
#> 5     dtprime           r96 TRUE FALSE
#> 6         fqd           txt TRUE FALSE
#> 7        rdes tsv, csv, txt TRUE  TRUE
#> 8    rdml-xml           xml TRUE  TRUE
#> 9        rdml     rdml, rdm TRUE  TRUE
#> 10 roche-lc96         lc96p TRUE FALSE

listRDMLFormats() reports, among other things, the registered format name, extensions, aliases, whether reading/writing/sniffing is available, the priority, API version, capabilities, and whether the handler is built in.

To see which reader or writer would be selected for a particular path:

detectRDMLFormat(
  filename,
  operation = "read"
)
#> [1] "rdml"

RDML7 first uses the extension and, when necessary, registered format sniffers. If several handlers remain equally suitable, use format = explicitly.

The repository includes readers for RDML/XML and several vendor or table formats. The exact supported set should be queried with listRDMLFormats() rather than assumed from a fixed list.

RDML7 object structure

RDML7 mirrors the hierarchy of the RDML schema. The principal top-level fields include:

  • dateMade
  • dateUpdated
  • id
  • experimenter
  • documentation
  • dye
  • sample
  • target
  • thermalCyclingConditions
  • experiment

The important hierarchy containing fluorescence data is approximately:

rdmlType
  `-- experiment
       `-- run
            `-- react
                 `-- data
                      |-- adp   amplification data points
                      `-- mdp   melting data points

S7 property access

RDML7 schema objects are S7 objects. Use $ to access their properties.

lc96$version
#> [1] "1.3"

lc96$experiment[[1]]$id$id
#> [1] "ca1eb225-ecea-4793-9804-87bfbb45f81d"

Collections such as experiments, runs, samples, and targets are keyed by their RDML identifiers. This makes it possible to inspect identifiers first and then select an element.

expname <- names(lc96$experiment)[1]

experiment <- lc96$experiment[[expname]]

names(experiment$run)
#> [1] "65aeb1ec-b377-4ef6-b03f-92898d47488b"

For routine data analysis, direct traversal of the full hierarchy is usually unnecessary. asTable() and getFData() provide a flatter interface.

Summarising and validating RDML data

summary()

Use summary() for a compact overview of an RDML object.

summary(lc96)

This is preferable to manually counting nested experiments, runs, reactions, targets, and curve types.

validateRDML() and isValidRDML()

RDML7 provides validation (as for RDML 1.3 version) functions in addition to S7 property validators.

validateRDML(lc96)

isValidRDML(lc96)

Use validation before exporting data or after programmatically modifying a large RDML object.

Visualising the hierarchy

asDendrogram() creates a dendrogram representation of the experiment structure.

asDendrogram(lc96)

This is the RDML7 replacement for the old x$AsDendrogram() method.

The standard scalar fields are:

  • fdataName — unique name used to identify a fluorescence series;
  • expId — experiment identifier;

  • mdp — melting data are present.

Advanced custom columns

For metadata not exposed as a built-in scalar field, ... also provides the current structured RDML objects:

experiment
run
react
data
samples
targets
dateMade
dateUpdated
id
experimenter
documentation
dye
thermalCyclingConditions

These objects are intended for advanced extraction. Because they are structured S7/RDML objects, they are not inserted directly into namePattern.

For example, a scalar property can be extracted from the current data object and then used as a template field:

tbl <- asTable(
  lc96,
  cq = data$cq,
  namePattern =
    "{position}:{sample}_{target}-{cq}"
)

Once cq is created as a scalar custom column, {cq} becomes available in namePattern.

This design means users do not need to know internal helper functions such as .rdmlIdChr(), .rdmlReactPosition(), or .rdmlSampleType() merely to construct an fdataName.

Example: deriving concentration from a sample name

User metadata can also be derived from existing scalar fields. For example, if a concentration is encoded as a separate underscore-delimited component of the sample name:


r96 <- readRDML(system.file(
  "extdata",
  "cd53_efficiency.r96",
  package = "RDML7"
))
concValues <- c("1", "0.5", "0.1", "0.01")

tbl <- asTable(
  r96,
  concentration = {
    parts <- strsplit(sample, "_", fixed = TRUE)[[1]]

    value <- parts[parts %in% concValues]

    if (length(value)) {
      as.numeric(value[[1]])
    } else {
      NA_real_
    }
  }
)

head(tbl)

This approach avoids falsely extracting a number that is only part of another identifier.

Legacy default and addColumns

default and addColumns may be retained for compatibility with older code, but new code should normally use:

columns + named expressions in ...

This gives asTable() a single, predictable column-selection model.

Adding or replacing fluorescence data

RDML7 uses value semantics. setFData() returns the modified object, so assign it back:

x <- setFData(x, ...)

Do not rely on the in-place mutation semantics of the old R6 implementation.

setFData() accepts:

  • a wide fluorescence table;
  • a description table;
  • fdataType = "adp" or "mdp";
  • conflict = "error", "keep", or "replace".

The fluorescence table has a first coordinate column (cyc or tmp) and one column per fluorescence series. The series names must match description$fdataName.

Merging RDML objects

Use mergeRDMLs() to combine RDML objects.

file1 <- system.file(
  "extdata",
  "lc96_bACTXY.rdml",
  package = "RDML7"
)

file2 <- system.file(
  "extdata",
  "stepone_std.rdml",
  package = "RDML7"
)

base <- readRDML(file1)
incoming <- readRDML(file2)

merged <- mergeRDMLs(
  base,
  incoming,
  dataConflict = "error"
)

asDendrogram(merged)

dataConflict controls what happens when equivalent data locations contain different values:

  • "incoming" — use the value from the incoming object;
  • "base" — preserve the value already present in the base object;
  • "error" — stop rather than resolve the conflict silently.

For merging independent files, "error" is useful while developing a pipeline because unexpected ID collisions become visible immediately.

A directory of files can be processed in a list:

files <- list.files(
  system.file("extdata", package = "RDML7"),
  full.names = TRUE
)

files <- files[!file.info(files)$isdir]

rdmls <- lapply(files, function(file) readRDML(file))
merged <- mergeRDMLs(
    rdmls,
    dataConflict = "error"
  )

merged <- mergeRDMLs(
    rdmls
  )
rm(rdmls)

asDendrogram(merged)
rm(merged)

If experiment identifiers are not unique between input files, rename them before merging.

Extending the file-format registry

One of the major additions in RDML7 is a public plugin API for file formats.

Registering a custom format

A format can provide:

  • file extensions;
  • a reader;
  • a writer.

The public registration function is:

registerRDMLFormat(
  name,
  extensions = character(),
  reader = NULL,
  writer = NULL,
)

For example, a third-party package could register a reader:

# simple-qpcr-reader.R -----------------------------------------------------
#
# Example third-party reader for RDML7's minimal format registry.

readSimpleQPCR <- function(fileName, ...) {
  lines <- readLines(
    fileName,
    warn = FALSE,
    encoding = "UTF-8"
  )

  section <- function(name) {
    start <- match(
      paste0("[", name, "]"),
      lines
    )

    if (is.na(start)) {
      stop(
        "Missing [",
        name,
        "] section",
        call. = FALSE
      )
    }

    nextSections <- grep(
      "^\\[[^]]+\\]$",
      lines
    )

    end <- nextSections[
      nextSections > start
    ]

    end <- if (length(end)) {
      end[[1L]] - 1L
    } else {
      length(lines)
    }

    out <- lines[
      seq.int(
        start + 1L,
        end
      )
    ]

    out[nzchar(trimws(out))]
  }

  # [meta] ---------------------------------------------------------------
  metaLines <- section("meta")

  meta <- strsplit(
    metaLines,
    "=",
    fixed = TRUE
  )

  meta <- stats::setNames(
    vapply(
      meta,
      function(x) {
        paste(
          x[-1L],
          collapse = "="
        )
      },
      character(1)
    ),
    vapply(
      meta,
      `[[`,
      character(1),
      1L
    )
  )

  requiredMeta <- c(
    "experiment",
    "run",
    "target",
    "dye"
  )

  missingMeta <- setdiff(
    requiredMeta,
    names(meta)
  )

  if (length(missingMeta)) {
    stop(
      "Missing metadata: ",
      paste(
        missingMeta,
        collapse = ", "
      ),
      call. = FALSE
    )
  }

  # [reactions] ----------------------------------------------------------
  reactions <- utils::read.delim(
    text = paste(
      section("reactions"),
      collapse = "\n"
    ),
    stringsAsFactors = FALSE,
    check.names = FALSE
  )

  requiredReactions <- c(
    "fdataName",
    "reactId",
    "sample",
    "sampleType",
    "quantity"
  )

  missingReactions <- setdiff(
    requiredReactions,
    names(reactions)
  )

  if (length(missingReactions)) {
    stop(
      "Missing reaction columns: ",
      paste(
        missingReactions,
        collapse = ", "
      ),
      call. = FALSE
    )
  }

  # [adp] ----------------------------------------------------------------
  fdata <- utils::read.delim(
    text = paste(
      section("adp"),
      collapse = "\n"
    ),
    stringsAsFactors = FALSE,
    check.names = FALSE
  )

  if (!identical(names(fdata)[[1L]], "cyc")) {
    stop(
      "First [adp] column must be `cyc`",
      call. = FALSE
    )
  }

  missingCurves <- setdiff(
    reactions$fdataName,
    names(fdata)
  )

  if (length(missingCurves)) {
    stop(
      "Missing fluorescence columns: ",
      paste(
        missingCurves,
        collapse = ", "
      ),
      call. = FALSE
    )
  }

  description <- data.frame(
    fdataName = reactions$fdataName,
    expId = meta[["experiment"]],
    runId = meta[["run"]],
    reactId = as.character(
      reactions$reactId
    ),
    sample = reactions$sample,
    sampleType = reactions$sampleType,
    target = meta[["target"]],
    targetDyeId = meta[["dye"]],
    quantity = as.numeric(
      reactions$quantity
    ),
    stringsAsFactors = FALSE
  )

  buildRDMLFromFData(
    fdata = fdata,
    description = description,
    fdataType = "adp",
    publisher = "simpleqpcr"
  )
}


registerRDMLFormat(

Loss-aware conversions

Different external formats do not necessarily represent every RDML feature. The importer/exporter API can describe known information loss using newRDMLLossRecord().

When developing a format plugin, declare known lossy transformations rather than silently discarding unsupported information.

This allows higher-level I/O code to decide whether loss should produce a warning, an error, or be explicitly allowed.

editRDML()

editRDML() remains available as an editing interface.

editRDML(lc96)

For reproducible analyses, scripted operations with asTable(), getFData(), setFData(), and the S7 object model should remain the primary workflow, while an editor is useful for interactive inspection and manual changes.

Working with external analysis packages

RDML7 intentionally keeps fluorescence extraction separate from downstream qPCR analysis. Once curves have been obtained with getFData(), they can be passed to other R packages.

For example:

curves <- getFData(
  lc96,
  dpType = "adp",
  longTable = FALSE
)

# The first column contains cycle coordinates.
cycles <- curves[[1]]

# Remaining columns contain fluorescence series and can be passed to
# modelling, preprocessing, Cq estimation, or visualisation code.

This separation allows RDML7 to focus on data interchange, metadata, validation, conversion, and object manipulation while specialised packages perform curve analysis.

See details and examples in Using RDML with other R packages vignette.

Recommended workflow

RDML7 public API naming convention rules

  • Actions start with a verb: readRDML(), validateRDML().
  • Conversion/coercion uses standard R as...: asTable(), asDendrogram(), asXML().
  • Predicates start with is...: isValidRDML().
  • Helper-object constructors start with new....
  • RDML schema/S7 type constructors keep the schema noun name: rdmlType(), sampleType(), targetType(), dataType(), etc.

Summary

RDML7 keeps the main ideas of the original RDML package—structured qPCR metadata, fluorescence extraction, table-based filtering, creation of RDML objects from user data, and interoperability with other R analysis packages—but substantially changes the implementation and public API.

The central concepts for new code are:

  1. read files with readRDML();
  2. treat rdmlType and nested schema elements as S7 objects;
  3. use asTable() as the metadata/curve index;
  4. use {field} templates for readable and documented fdataName generation;
  5. add custom asTable() columns directly through ...;
  6. use getFData() and setFData() for fluorescence;
  7. remember that modification uses value semantics;
  8. validate with validateRDML() / isValidRDML();
  9. write through writeRDML();
  10. discover and extend formats through the format registry.

For the current runtime list of supported file handlers, always prefer:

listRDMLFormats()

over a hard-coded list in analysis code.
